# SQLD 과목 2 오답노트

## SQL 명령어 분류
- DML (조작): SELECT, INSERT, UPDATE, DELETE
- DDL (정의): CREATE, ALTER, DROP, TRUNCATE
- DCL (권한): GRANT, REVOKE
- TCL (트랜잭션): COMMIT, ROLLBACK, SAVEPOINT
- 함정: TRUNCATE는 DDL (롤백 불가), DELETE는 DML (롤백 가능)

## NULL의 연산
- NULL은 '값이 없음' → 연산이나 비교 결과가 전부 NULL
- NULL + 100 = NULL (0 아님)
- 판별은 IS NULL / IS NOT NULL 로만 (= NULL 안 됨)
- NULL 대체 함수: NVL, COALESCE

## 부정 비교 연산자
- ANSI 표준: `<>`
- 그 외 (DBMS 지원): `!=`, `^=`
- 셋 다 '같지 않음'으로 동일한 의미
- NOT IN (...): 목록에 NULL 있으면 결과가 안 나올 수 있음 (주의)

## 문자 함수
- LTRIM(문자열, [제거문자]): 왼쪽에서 지정 문자 제거 (기본값 공백)
  - LTRIM('xxabc', 'x') → 'abc'
  - 오른쪽 RTRIM, 양쪽 TRIM
- CONCAT(a, b): 두 문자열 연결
  - Oracle은 인자 2개만 (3개 이상은 || 사용)
  - CONCAT('SQL', 'D') → 'SQLD'

## GROUP BY 와 HAVING
- GROUP BY: 컬럼 기준으로 행을 그룹으로 묶음
- HAVING: 그룹핑된 결과에 조건 (집계함수 조건은 여기)
- WHERE vs HAVING: WHERE는 그룹핑 전 행 필터 / HAVING은 그룹핑 후 그룹 필터
- 집계함수(COUNT, SUM 등) 조건은 WHERE 못 씀 → HAVING

## SELECT 문 순서
- 작성 순서: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
- 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
- 핵심: SELECT가 거의 마지막 실행 → SELECT에서 만든 별칭을 WHERE에서 못 쓰는 이유
- ORDER BY는 맨 마지막 실행이라 별칭 사용 가능

## 별칭(ALIAS)이란
- 컬럼이나 테이블에 임시로 붙이는 다른 이름
- 컬럼 별칭: SELECT name AS 이름 → 결과 헤더가 '이름'으로 표시
  - AS는 생략 가능: SELECT name 이름
- 테이블 별칭: FROM member m → 이후 m.name 처럼 짧게 참조
- 주의: 실행 순서상 SELECT에서 만든 별칭은 WHERE, GROUP BY, HAVING에서 못 씀
  - ORDER BY에서만 사용 가능 (맨 마지막 실행이라서)
